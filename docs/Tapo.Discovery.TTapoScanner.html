type TTapoScanner = class(TObject)

Description

Finds Tapo devices on the local network and adds them to a TTapoClient.

Nothing happens until ScanAsync or Scan is called. Devices found are added to the client and stay there, so the scan is needed only when devices are first set up or when one has been added to the network.

Addresses the client already has are reported as tssKnown and not probed again, so rescanning is cheap for devices already found.

One scan at a time per scanner. The scanner must be freed on the main thread; freeing it waits for a probe stage under way to stop.

Example: 

FScanner := TTapoScanner.Create(FClient);
FScanner.OnProgress := ScanProgress;
FScanner.ScanAsync('192.168.1.0', '255.255.255.0',
  procedure(const R: TTapoScanResult; const Err: string)
  var
    E: TTapoScanEntry;
  begin
    for E in R do
      if E.IsTapo then
        Memo1.Lines.Add(E.IP + '  ' + E.Device.ClassName + '  ' + E.Nickname);
  end);

Public procedure ScanAsync(const ANetwork, ASubnet: string; const AOnComplete: TTapoScanCompleteProc = nil);

Scans a subnet in the background and adds the Tapo devices found to the client.

Call it from the main thread. Progress, OnDeviceFound and AOnComplete all run on the main thread. Errors (a bad subnet, an unsupported platform) arrive in AOnComplete's AError.

LastResult is set before AOnComplete is called.

Public procedure Cancel;

Asks the scan under way to stop.

The ARP stage cannot be interrupted, so a scan cancelled during it stops when that stage ends, before any probing. During the probe stage, logins already started finish and the rest are skipped (tssCancelled). The scan then ends with AError 'Scan cancelled'.

Public function Devices: TArray<TTapoDevice>;

The Tapo devices in LastResult (tssAdded and tssKnown).

A device freed since the scan is still listed until the next scan. Client.Devices[] always reflects the current set.

Returns

The devices, owned by the client, in address order.

The entries of the last scan that reached the probe stage, including one cancelled during probing. Empty until then.

Public property TpLinkOnly: Boolean read FTpLinkOnly write FTpLinkOnly;

True (the default) keeps only TP-Link MAC prefixes after the ARP stage. False probes every host found, which is slower but also finds a device with a MAC prefix missing from NetMacScan's table.

Public property TcpSweepFallback: Boolean read FTcpSweepFallback write FTcpSweepFallback;

True (the default): when the ARP table cannot be read, find candidates by trying TCP ports 80 and 443 on every address instead. Slower, and candidates then have no MAC, but every one is still checked by logging in.

macOS can hide the ARP table from an app even when it may use the local network. The reason the ARP stage failed is in LastArpError.

Public property SweepTimeout: Integer read FSweepTimeout write FSweepTimeout;

How long the TCP sweep waits for each connection, in ms; the default is 1500.

Public property LastArpError: string read GetLastArpError;

Why the ARP stage of the last scan failed, when the TCP sweep was used instead; empty when the ARP stage worked.

Public property MaxParallel: Integer read FMaxParallel write FMaxParallel;

How many candidates are probed at once, 1 to 32. The default is 8.

Public property ProbeConnectionTimeout: Integer read FProbeConnectionTimeout write FProbeConnectionTimeout;

The connection timeout while probing, in ms; the default is 2000. Only the probes use it: devices added keep the client's own timeouts.

Public property ProbeResponseTimeout: Integer read FProbeResponseTimeout write FProbeResponseTimeout;

The response timeout while probing, in ms; the default is 8000. A TPAP login on a bulb can take a few seconds, so do not set it too low.

Public property RetryConnectionTimeout: Integer read FRetryConnectionTimeout write FRetryConnectionTimeout;

The connection timeout, in ms, of one more try for each candidate that gave no response at first; the default is 6000. 0 turns the retry off.

Wi-Fi bulbs in power save can answer the ARP stage and still miss the short ProbeConnectionTimeout. The retry runs after all candidates have had their first try, so it costs time only when something did not answer.

Public property OnProgress: TTapoScanProgressEvent read FOnProgress write FOnProgress;

Public property OnDeviceFound: TTapoScanDeviceEvent read FOnDeviceFound write FOnDeviceFound;
