Description

On-demand discovery of Tapo devices on the local network.

The scan has two stages:
  1. ARP stage: NetMacScan (https://github.com/peardox/NetScan) lists the
     hosts that answer on the subnet with their MAC addresses. By default
     only TP-Link MAC prefixes are kept; that list still holds routers,
     range extenders, Deco units and other TP-Link kit.
  2. Probe stage: each candidate is checked with AddDetected on a private
     client with short timeouts. A real Tapo device is then added to your
     client as the right class, already logged in. Anything else is
     reported with the reason and left out.

If the ARP table cannot be read (macOS can hide it from an app), stage 1 is replaced by a TCP sweep: every address is tried on port 80 (plugs, lights, hubs) and, if something answers there with a refusal, on 443 (cameras). See TcpSweepFallback and LastArpError.

A scan is slow (seconds for the ARP stage, plus a login per Tapo device), so it only runs when you ask for one. The devices it adds stay in the client, so later code uses Client.Find, Client.Devices[] or Scanner.Devices without scanning again. 

Scanner := TTapoScanner.Create(Client);
Scanner.ScanAsync('192.168.1.0', '/24',
  procedure(const R: TTapoScanResult; const Err: string)
  begin
    for Dev in Scanner.Devices do
      Memo1.Lines.Add(Dev.Host + '  ' + Dev.ClassName);
  end);

Devices are added by IP address. Give them DHCP reservations in the router so the addresses do not change between scans.

Needs NetMacScan.pas from the NetScan repository on the search path. Windows, macOS and Linux only: Android and iOS do not let apps read the ARP table (CheckCandidates and CheckHosts work everywhere).

TTapoScanStatus = (...);

What a scan found at one address.

Values
  • tssAdded: A Tapo device, added to the client by this scan.
  • tssKnown: A device the client already had at this address. It was not probed again.
  • tssNoResponse: Nothing answered on port 80 or 443: not a Tapo device.
  • tssRejected: Something answered but did not log in as a Tapo device. Either it is not one (a router, say), or it is one these credentials do not open. The reason is in TTapoScanEntry.Error.
  • tssBadCredentials: A Tapo device that rejected the account e-mail or password. If no device of the scan accepted them either, the credentials are wrong.
  • tssUnsupported: A Tapo device that logged in, of a model that is not supported.
  • tssLockedOut: A Tapo device that has locked itself after too many failed logins (error -2101).
  • tssCancelled: Not probed, because the scan was cancelled first.
TTapoScanResult = TArray<TTapoScanEntry>;

The result of a scan: one entry per candidate, in address order.

TTapoScanStage = (...);

The stage a progress report is about.

Values
  • tsgArp: Finding hosts and their MAC addresses (NetMacScan).
  • tsgSweep: Only when the ARP table cannot be read: finding hosts that accept a TCP connection on port 80 or 443.
  • tsgProbe: Checking each candidate for a Tapo device.
TTapoScanProgressEvent = procedure(Sender: TObject; AStage: TTapoScanStage; ADone, ATotal, AFound: Integer) of object;

Progress of a scan. Always called on the main (UI) thread.

Each stage starts with ADone = 0 and ends with ADone = ATotal, so a progress bar can take its Max from the first call of each stage.

Parameters
Sender
The scanner.
AStage
The stage being reported.
ADone
tsgArp and tsgSweep: addresses checked so far. tsgProbe: candidates checked so far.
ATotal
tsgArp and tsgSweep: addresses in the subnet. tsgProbe: candidates from the ARP stage or the sweep.
AFound
tsgArp and tsgSweep: candidates found so far. tsgProbe: Tapo devices found so far.
